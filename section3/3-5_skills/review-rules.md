# レビュー観点（このファイルを指定して Skill を作らせてください）

渡されたコードを、次の4つの観点でレビューしてください。
指摘は「観点 / 該当箇所 / 何が問題か / どう直すか」の順で、具体的に書いてください。

## 1. セキュリティ

- 文字列連結でSQLを組み立てていないか（プレースホルダを使っているか）
- 認証・認可のチェックが必要な箇所で抜けていないか
- 秘密情報（トークン・パスワード・APIキー）をソースに直書きしていないか
- パスワードのハッシュに脆弱なアルゴリズム（MD5・SHA-1）を使っていないか

## 2. 機能性・正しさ

- 例外やエラー時の戻り値が呼び出し側で扱える形になっているか
- 境界値（空・0・None・最大件数）で破綻しないか
- リソース（DB接続・ファイル）が例外時にも確実に閉じられるか

## 3. パフォーマンス

- 必要以上のデータを取得していないか（ページングをアプリ側で切っていないか）
- ループの中で重い処理（クエリ・I/O）を繰り返していないか

## 4. 可読性・規約

- 命名が役割を表しているか
- `== None` ではなく `is None` など、言語の慣用表現に沿っているか
- 分岐が深すぎないか、1関数が長すぎないか

## 出力形式

- 重要度の高い順に並べる
- 各指摘に「重要度: 高 / 中 / 低」を付ける
- 最後に、良かった点を1〜2行添える
