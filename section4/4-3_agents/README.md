# 4-3 サブエージェント（Agentツール）ワーク

`src/` のコードを題材に、**観点の違うレビュー担当を2つ**作って、同じコードに並列でぶつけます。
エージェント定義は手で書かず、**やりたいことを言葉で伝えて Claude Code に作ってもらいます**。

1. このフォルダで `claude` を起動し、そのまま自然言語で2つまとめて作ってもらう

   ```text
   src/ をレビューするエージェントを2つ作って。security-reviewer は脆弱性、performance-reviewer は性能問題を見る役割で。
   ```

   → `.claude/agents/security-reviewer.md` と `.claude/agents/performance-reviewer.md` が作られる
2. 生成された2つの定義ファイルを開いて中身を確認する（ここが一番大事）
   - フロントマターの `name` … エージェントの名前（`@agent-security-reviewer` のように呼び出せる）
   - フロントマターの `description` … どういうときにこのエージェントが呼ばれるか
   - 本文 … このエージェント自身への指示。振る舞いを決めるのはここ

   **2つを見比べる**と、`description` が「呼ばれるタイミング」を、本文が「見るべき観点」を
   分担していることがはっきり分かります。

   ※ `name`・`description` 以外にどんな項目が付くかは生成のたびに変わります。
   実際に開いたファイルを見て確認してください。内容を直したいときは
   「性能側はアルゴリズムの計算量を重点的に見て」のように言葉で伝えれば直せます
3. 2つに同時にレビューを依頼する

   ```text
   @agent-security-reviewer と @agent-performance-reviewer で src/ をレビューして
   ```

   ※ **作成直後のサブエージェントは、`@` を押しても補完候補に出ないことがあります。**
   その場合は `/exit` で一度抜けて `claude` を起動し直すと候補に出てきます
4. `/tasks` で、**2件が同時に走っている**ことを確認する
5. 観点の違う2つの結果が返ってくることを確認する
   - security-reviewer … パストラバーサル、コマンドインジェクション、`eval` による任意コード実行、
     `Math.random()` による予測可能なトークン、XSS など
   - performance-reviewer … 二重ループによる O(n²)、ループ内での正規表現の再生成、
     `await` の直列実行、`unshift` の繰り返し、同期I/O など
6. `/context` で、メインの会話のコンテキスト消費が小さいままであることを確認する

`/tasks` に2件同時に並んだこと、観点の違う2つの結果が返ったこと、`/context` の消費が
小さいままであることの3点が確認できればこのワークは合格です。

1人のエージェントに「セキュリティも性能も見て」と頼むこともできますが、その場合は
順番に1つずつ処理されます。**役割を分けて並列に走らせられる**のがサブエージェントの利点です。

## 題材のコードについて

`src/` の2ファイルは、レビューの題材としてあえて問題を残してあります。動かすためのものではありません。

| ファイル | 内容 |
|---|---|
| `src/fileService.js` | 社内向けの資料ダウンロードサービス |
| `src/reportBuilder.js` | アクセスログから月次レポートを組み立てる処理 |
